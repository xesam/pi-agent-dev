## 附录：概念速查表、FAQ 与延伸阅读

### A. 概念关系图

先把前面散落的概念放进一张关系图，帮你在脑子里定位它们各在哪一层：

```
┌──────────────────────────────────────────────────┐
│ Session（一次完整会话：最外层容器）              │
├──────────────────────────────────────────────────┤
│   System Prompt ── 开场设定你是谁、怎么做事      │
├──────────────────────────────────────────────────┤
│   Context = messages（一直增长，见第1章）        │
├──────────────────────────────────────────────────┤
│   ┌─ Agent Loop（决定→调工具→喂回→再决定）       │
│   │    Tool：每轮可调（read/write/bash…）        │
│   └────────────────────────────────────────      │
└──────────────────────────────────────────────────┘

Pi 给你加能力的三个机制，分别作用在哪一层：
  Prompt Template → 填进 Context 开头的内容
  Skill           → 塞进 System Prompt 的"按需说明书"
  Extension       → 新增 Tool / 拦截 Loop 里的事件
```

### B. 概念速查表

| 概念 | 一句话解释 | 详见 |
|------|-----------|------|
| Agent Loop | "模型决定 → 工具执行 → 结果喂回 → 模型再决定"的循环，是所有 Agent 的核心 | Ch1 |
| Tool（工具） | 模型能调用的一个具体动作（读文件、跑命令、delegate 给别的角色……） | Ch1, Ch5d |
| Session（会话） | 一次完整的对话历史 + 状态，可持久化、可 fork、可续接 | Ch4 |
| System Prompt | 决定"模型现在扮演谁、该怎么做事"的那段固定文本 | Ch3, Ch6a |
| Extension | 用 TypeScript 写的、给 Pi 加新工具/新命令/事件拦截的模块 | Ch5, Ch5d |
| Skill | 一个带 `SKILL.md` 的目录，模型按需读取的"操作手册"，渐进式披露 | Ch5, Ch5c |
| Prompt Template | 存成 `.md` 文件的常用 prompt，`/文件名` 触发 | Ch5, Ch5b |
| Pi Package | 打包 Extensions/Skills/Prompts 供分发安装的 npm/git 包 | Ch5.4 |
| `createAgentSession` | SDK 核心函数，创建一个独立的 Agent 会话（子 Agent 或嵌入程序） | Ch6a, Ch6d |
| 工具白名单 | `tools` 参数限制子 Agent 能用的工具——安全边界靠它而非 prompt | Ch6a, Ch6c |
| 软约束 vs 硬约束 | prompt 说"别删文件"=软约束；不给 bash 工具=硬约束 | Ch6c |
| `pi.appendEntry` | 往会话历史写自定义条目，实现状态持久化和分支跟随 | Ch6b |
| `submit_review` | Reviewer 专属的结构化结论提交工具 | Ch6c |
| `MAX_CODER_DELEGATIONS` | 代码层熔断：限制 Coder 被委派次数，防无限循环 | Ch6c |
| AbortSignal 传播 | 工具的 `signal` 参数接到子 `session.abort()`，取消上层也停子 Agent | Ch6a, Ch6c |

### C. FAQ 速查

#### 安装与配置

**Q: `npm install -g` 报权限错误？**
用 `nvm` 管理 Node.js 版本，或加 `sudo`（不推荐）。更好的方式是用 `nvm` 后不需要 `sudo`。

**Q: 安装后 `pi` 命令找不到？**
运行 `npm bin -g` 查看全局 bin 目录，确认它在 `PATH` 里。

**Q: 怎么用本地模型（Ollama / llama.cpp）？**
参考官方 [llama-cpp 文档](https://pi.dev/docs/latest/llama-cpp)，或用 `pi.registerProvider` 注册自定义 provider。

**Q: Windows 上 bash 工具不可用？**
用 `pi --tools read,powershell,edit,write` 替换 bash 为 powershell。

#### 日常使用

**Q: 模型不调我注册的自定义工具？**
检查 `description` 是否写清楚了"什么时候该用"。模型靠 description 决定要不要调工具。

**Q: context 占用满了怎么办？**
用 `/compact` 压缩历史对话。它会总结前面的内容腾出空间，不是清空。

**Q: `/fork` 和 `/clone` 有什么区别？**
`/fork` 从当前点分叉（新分支只包含从当前点往后的新对话）；`/clone` 整段照搬（完整复制全部历史）。

**Q: 怎么让 Pi 只读不改代码？**
`pi --tools read,grep,find,ls -p "你的任务"`，或在 SDK 里设 `tools: ["read", "grep", "find", "ls"]`。

#### 扩展开发

**Q: Extension 和 Skill 怎么选？**
只给模型"一份操作指南"→ Skill；要给 Pi 新增一个能力（新工具、拦截事件、加命令）→ Extension。

**Q: 子 Agent 会话为什么要 `appendSystemPromptOverride: () => []`？**
不设置的话 Pi 会自动追加 `APPEND_SYSTEM.md` 的内容，污染你精心定制的角色 prompt。

**Q: `throw` 和 `return` 在工具 `execute` 里有什么区别？**
`throw` 才算失败，`return` 一个值永远不会被标记为出错。

**Q: 枚举参数用什么定义？**
用 `StringEnum(["a","b"] as const)`，别用 `Type.Union`/`Type.Literal`——后者在 Google API 上不工作。

**Q: `ctx.ui.confirm` 在 `pi -p` 模式下能用吗？**
不能。`ctx.ui.confirm` 只在 TUI 交互模式下有效。用 `ctx.hasUI` 判断。

**Q: 怎么持久化扩展状态？**
用 `pi.appendEntry` 写入会话历史，在 `session_start` 和 `session_tree` 事件里重建。参考 Ch6b 和官方 `todo.ts` 示例。

### D. 框架对比

| 维度 | Pi | Claude Code | Cursor | Aider | LangChain Agent |
|------|----|----|--------|-------|-----------------|
| 形态 | CLI + SDK | CLI | IDE 插件 | CLI | 库 |
| 模型绑定 | 不绑定（20+ 家） | 仅 Anthropic | 多模型 | 多模型 | 不绑定 |
| 扩展机制 | Extension/Skill/Prompt | MCP | 配置 | 配置 | 纯代码 |
| 子 Agent | 扩展实现 | 内置 | 无 | 无 | 代码实现 |
| 权限模型 | 用户权限（靠扩展加沙箱） | 内置确认 | IDE 权限 | 用户权限 | 开发者控制 |
| 会话管理 | 树状分支/fork/clone | 线性 | 无 | git 块 | 开发者控制 |
| 上下文管理 | `/compact` 自动压缩 | 自动截断 | 手动管理 | git diff 管理 | 开发者控制 |
| 适合场景 | CLI 编码、CI、自定义工作流 | Anthropic 生态 | IDE 编码 | git 工作流 | 嵌入应用 |
