## 第 3 章：安装与第一次运行

### 3.1 安装

```bash
npm install -g --ignore-scripts @earendil-works/pi-coding-agent
```

`--ignore-scripts` 不是可选项的装饰——Pi 官方文档特别强调"正常安装不需要执行安装脚本"，所以显式禁用它是推荐做法（减少被恶意 postinstall 脚本攻击的面）。

卸载时注意：卸载包本身不会清掉 `~/.pi/agent/` 目录，里面留着你的设置、登录凭证、历史会话和已安装的 pi 包。

### 3.2 认证：两种方式

**方式一：订阅登录**（推荐，如果你已经有相关订阅）

```bash
pi
/login
```

支持 Claude Pro/Max、ChatGPT Plus/Pro（Codex）、GitHub Copilot 订阅登录，不用管 API Key。

**方式二：API Key**

```bash
export ANTHROPIC_API_KEY=sk-xxx
pi
```

或者同样用 `/login` 把 Key 存到认证文件里。

### 3.3 跑起来

```bash
cd 你的项目目录
pi
```

进去之后随便打一句话，比如：

```
总结一下这个仓库是做什么的，并告诉我怎么跑它的测试
```

模型这时候会自己决定调用 `read`/`grep`/`ls` 之类的工具去翻文件，这就是你第一次亲眼看到 Agent Loop 在跑。

**你会看到什么**：界面里会冒出一条模型调用工具的记录（比如 `read package.json`），紧接着是工具返回的内容，然后模型可能再调一次工具……几轮之后它会停下来，用一段文字总结答案。注意每调一次工具，那条工具结果就进了 `messages`——第 1 章说的“context 只增不减”，你现在能直接看到它在涨。如果答案不对，多半是模型一开始翻错了文件，你再补一句话纠正它就行，不用重开会话。

### 3.4 项目上下文：AGENTS.md

Pi 启动时会自动加载"上下文文件"，让模型了解你项目的特殊规则：

- 全局：`~/.pi/agent/AGENTS.md`
- 项目：当前目录及父目录里的 `AGENTS.md` 或 `CLAUDE.md`

改完这些文件后用 `/reload` 让它生效，不用重启整个进程。

这个机制非常重要——后面我们做多角色团队时，会给每个"角色"单独定制它的系统提示词，本质上跟这里是同一个思路：**用文本告诉模型"你现在是谁、该怎么做事"**。

### 3.5 常见问题排错

| 问题 | 解决方法 |
|------|----------|
| `npm install` 报错或超时 | 用 `--ignore-scripts`；检查 npm registry 是否可达；尝试 `npm cache clean --force` 后重试 |
| 安装成功但 `pi` 命令找不到 | 检查 npm 全局 bin 目录是否在 `PATH` 里；用 `npm bin -g` 查路径 |
| `/login` 登录失败 | 检查网络连通性；确认你的订阅是否支持；尝试用 API Key 方式替代 |
| 进入 pi 后无响应 | 检查模型是否可用（`/model`）；确认 API Key 环境变量或已 `/login` |
| Windows 下 `bash` 工具报错 | Windows 不自带 bash，考虑用 `powershell` 工具替代（`pi --tools read,powershell,edit,write`） |
| 想用本地模型（Ollama 等）| 参考官方 [llama-cpp 文档](https://pi.dev/docs/latest/llama-cpp)，配置自定义 provider |
| 卸载后配置还在 | 正常行为——`~/.pi/agent/` 不会随包卸载清除，手动删除即可 |
