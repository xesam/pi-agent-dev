## 第 7b 章：设计模式速查——从官方示例提取的 8 个模式

写自己的扩展时，你不需要从零发明。Pi 官方仓库的 `examples/extensions/` 里有 50+ 个可运行示例，它们反复使用了几个高频设计模式。这一章把这些模式提取出来，做成速查表——你遇到什么需求，查表找到对应模式，拿核心代码片段改改就能用。

### 模式 1：自定义工具（registerTool）

**什么时候用**：你想让模型能做一件 Pi 默认做不到的事——查数据库、调 API、生成报告……

**核心代码**：

```typescript
pi.registerTool({
  name: "my_tool",
  label: "My Tool",
  description: "做什么用、什么时候该调用",  // ← 这行是关键
  parameters: Type.Object({
    input: Type.String({ description: "参数说明" }),
  }),
  async execute(_id, params) {
    // 你的逻辑
    return { content: [{ type: "text", text: "结果" }], details: {} };
  },
});
```

**常见坑**：
- `description` 写得太笼统模型不调用——要说清楚"什么时候用"
- 用 `typebox` 定义参数，别手写 JSON Schema
- 需要枚举参数时用 `StringEnum(["a","b"] as const)`，别用 `Type.Union`

**官方参考**：`examples/extensions/hello.ts`、`tools.ts`

### 模式 2：事件拦截（tool_call + block）

**什么时候用**：你想在工具执行**之前**检查或修改——拦危险命令、保护路径、修改参数。

**核心代码**：

```typescript
pi.on("tool_call", async (event, ctx) => {
  if (event.toolName === "bash") {
    const cmd = event.input.command as string;
    if (cmd.includes("rm -rf")) {
      const ok = await ctx.ui.confirm("危险", "确定？");
      if (!ok) return { block: true, reason: "被拦截" };
    }
    // 也可以修改参数（不阻止，只改）
    event.input.command = `source ~/.profile\n${cmd}`;
  }
});
```

**常见坑**：
- `return { block: true }` 阻止执行；不 return 或 `return undefined` 放行
- `event.input` 可直接修改——修改后模型看到的工具参数会变
- `ctx.ui.confirm` 只在 TUI 模式有效，`pi -p` 下没有 UI

**官方参考**：`confirm-destructive.ts`、`protected-paths.ts`、`inline-bash.ts`

---

### 模式 3：状态持久化（appendEntry + 重建）

**什么时候用**：你的扩展有状态（开关、计数器、待办列表），希望状态跟会话分支走——fork 后状态正确。

**核心代码**：

```typescript
// 写入
pi.appendEntry("my-state", { count: 42 });

// 重建（在 session_start 和 session_tree 时调用）
const reconstruct = (ctx: ExtensionContext) => {
  for (const entry of ctx.sessionManager.getBranch()) {
    if (entry.type === "custom" && entry.customType === "my-state") {
      const data = entry.data;
      // 用 data 恢复内存状态
    }
  }
};

pi.on("session_start", async (_e, ctx) => reconstruct(ctx));
pi.on("session_tree", async (_e, ctx) => reconstruct(ctx));
```

**常见坑**：
- 如果不用 `appendEntry`，只用内存变量——fork 后两个分支共享同一个变量，互相干扰
- 重建时要从后往前扫——用最后一条记录的状态

**官方参考**：`todo.ts`（最完整的状态管理示例）

### 模式 4：子 Agent 委派（createAgentSession）

**什么时候用**：你想让主 Agent 把任务"外包"给一个有独立人设、独立工具集、独立对话历史的子 Agent——多角色、多步骤工作流。

**核心代码**：

```typescript
const { session } = await createAgentSession({
  cwd: ctx.cwd,
  sessionManager: SessionManager.inMemory(),
  modelRuntime,
  tools: ["read", "grep", "find", "ls"],      // 子 Agent 的工具白名单
  systemPromptOverride: () => "你是审查员...",
  appendSystemPromptOverride: () => [],
});

// 收集输出
let output = "";
const unsub = session.subscribe((event) => {
  if (event.type === "message_update" &&
      event.assistantMessageEvent.type === "text_delta") {
    output += event.assistantMessageEvent.delta;
  }
});

// 接取消信号
const onAbort = () => void session.abort();
signal.addEventListener("abort", onAbort, { once: true });

try {
  await session.prompt("审查任务...");
} finally {
  unsub?.();
  signal.removeEventListener("abort", onAbort);
  session.dispose();
}

return { content: [{ type: "text", text: output }], details: {} };
```

**常见坑**：
- 忘记 `dispose()` → 资源泄漏
- 忘记接 abort signal → 用户取消后子 Agent 还在后台跑
- `appendSystemPromptOverride: () => []` 不设 → 默认 prompt 污染角色人设
- `tools` 不限制 → 子 Agent 拿到全部工具，安全边界失效

**官方参考**：`subagent/`（进程级子 Agent）、本教程 `multi-role/index.ts`（in-memory 子 Agent）

### 模式 5：自定义 UI 渲染（renderCall / renderResult）

**什么时候用**：你想让工具调用在 TUI 里有更好的显示——卡片、颜色、折叠/展开。

**核心代码**：

```typescript
pi.registerTool({
  name: "my_tool",
  // ... parameters, execute ...

  renderCall(args, theme, _context) {
    // 自定义工具调用时的显示
    return new Text(
      theme.fg("toolTitle", theme.bold("my_tool ")) +
      theme.fg("accent", args.target),
      0, 0
    );
  },

  renderResult(result, { expanded }, theme, _context) {
    const text = result.content[0];
    return new Text(text?.type === "text" ? text.text : "", 0, 0);
  },
});
```

**要点**：
- `renderCall` 接收工具参数，返回一个 TUI 组件
- `renderResult` 接收工具结果，`expanded` 布尔值表示用户是否按了 Ctrl+O 展开
- 可以用 pi-tui 的 `Container`、`Text`、`Markdown`、`Spacer` 等组件组合复杂 UI
- `ctx.ui.theme` 提供主题颜色——用 `theme.fg("accent", text)` 而不是硬编码颜色

**官方参考**：`todo.ts`（待办列表渲染）、`subagent/index.ts`（多模式渲染）、`message-renderer.ts`

### 模式 6：自定义压缩（session_before_compact）

**什么时候用**：你不满意 Pi 默认的上下文压缩策略，想自己控制怎么总结历史对话。

**核心代码**：

```typescript
pi.on("session_before_compact", async (event, ctx) => {
  // event.preparation 有压缩前的准备数据
  // event.reason 是 "manual" | "threshold" | "overflow"

  // 方式一：取消压缩
  return { cancel: true };

  // 方式二：提供自定义总结
  return {
    compaction: {
      summary: "自定义总结内容...",
      firstKeptEntryId: event.preparation.firstKeptEntryId,
      tokensBefore: event.preparation.tokensBefore,
    },
  };
});
```

**官方参考**：`custom-compaction.ts`

### 模式 7：输入转换（input 事件）

**什么时候用**：你想在用户输入到达模型之前改写它——加前缀、替换关键词、路由到不同处理逻辑。

**核心代码**：

```typescript
pi.on("input", async (event, ctx) => {
  // 改写输入
  if (event.text.startsWith("?quick ")) {
    return { action: "transform", text: `简短回答：${event.text.slice(7)}` };
  }

  // 完全拦截（不发给模型）
  if (event.text === "ping") {
    ctx.ui.notify("pong", "info");
    return { action: "handled" };
  }

  // 默认放行
  return { action: "continue" };
});
```

**三种返回值**：
- `continue` — 原样传给模型（默认）
- `transform` — 改写后传给模型
- `handled` — 不传给模型，扩展自己处理

**官方参考**：`input-transform.ts`、`input-transform-streaming.ts`

### 模式 8：进程级隔离（spawn 子进程 vs in-memory 会话）

**什么时候用**：你有两种"子 Agent"实现方式可选——

| 方式 | 机制 | 优点 | 缺点 |
|------|------|------|------|
| **in-memory 会话** | `createAgentSession()` 在同进程内创建 | 快、共享 `ModelRuntime` | 子 Agent 崩溃可能影响主进程 |
| **子进程** | `spawn("pi", ["--mode", "json", "-p", ...])` | 完全隔离、崩溃不影响主进程 | 慢（启动开销）、需要 JSON 通信 |

**in-memory 方式**（本教程 Ch6a/Ch6c 用的）：

```typescript
const { session } = await createAgentSession({
  sessionManager: SessionManager.inMemory(),
  modelRuntime,
  // ...
});
await session.prompt("任务");
session.dispose();
```

**子进程方式**（官方 `subagent/` 用的）：

```typescript
import { spawn } from "node:child_process";

const proc = spawn("pi", ["--mode", "json", "-p", "--no-session", "任务"], {
  stdio: ["ignore", "pipe", "pipe"],
});

proc.stdout.on("data", (data) => {
  // 解析 JSON 事件流
  const event = JSON.parse(data.toString());
  // ...
});
```

**选型原则**：
- 需要快速迭代、共享模型配置 → in-memory
- 需要强隔离（不同工具集、不同模型、不同权限）→ 子进程
- 本教程的 multi-role 用的是 in-memory（简单、快）；官方的 subagent 用的是子进程（隔离性更好、支持并行）
