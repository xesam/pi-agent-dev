## 第 1 章：什么是 AI Agent？

你已经会调用 LLM API 了，所以下面这件事不需要再讲：拼一个 `messages` 数组，调一次 `create()`，拿到一段文字。一问一答，一次调用就结束。

```
messages = [{ role: "user", content: "…" }]
       → create(messages)
       → 一段文字回复，调用结束
```

**Agent 和这一步的差别，只在于多了一个循环。** 你大概也调过 function calling / tool use，但很可能把它当成"让模型吐一段结构化 JSON"用——调一次、拿到参数、完事。Agent 把它当成**循环的驱动器**：模型不再直接回答你，而是先说"我要调用 `read` 工具"，你执行这个工具、把结果作为一条新 message 塞回 `messages`，**再调一次 API**；模型看到工具结果后决定下一步，可能再要一个工具，也可能说"我搞定了，答案是……"，循环才结束。

如果想更容易理解 Agent，可以参考：[《从零理解 AI Agent》](https://github.com/xesam/from-chat-to-agent) 这个更基础的教程。


```
你给一个任务
   ↓
┌→ 模型决定下一步
│      │
│      ├─ 不再调工具 ──→ 输出最终文字，结束
│      │
│      └─ 要调工具 ──→ 执行工具 ──→ 结果塞回 messages
│                                          │
└──────────────────────────────────────────┘
（带着工具结果，回到模型，再决定下一步）
```

这个"决定 → 执行 → 把结果喂回去 → 再决定"的循环，就是 **Agent Loop（智能体循环）**。换句话说，**Agent 不是一种新模型，而是围绕模型写的一段循环代码**。所有 Agent 框架（Pi、Claude Code、Cursor、LangGraph……）的核心其实都是这一件事，区别只在于三个旋钮：

- **配了哪些工具**（读文件？写文件？跑命令？调 API？甚至"再起一个子 Agent"）
- **循环什么时候停**（模型自己判断完成？还是每个工具都要人确认？）
- **怎么管理上下文**——这一点对你来说尤其重要：每一轮的工具调用结果都会作为新 message 进 `messages`，**context 只增不减**，token 一直在涨。运行稍久就会撞上模型的 context window，要么报错要么被悄悄截断。所以"管理上下文"不是可选项，而是任何跑得长一点的 Agent 都必须面对的问题（Pi 里的 `/compact` 命令就是干这个的，第 4 章会讲）。

Pi 就是一个把这套 Agent Loop 做成了产品的开源工具，而且它的设计哲学非常克制：**核心极小，几乎所有能力都靠扩展加上去**。这也是为什么这篇教程能带你"从认识到扩展"——因为在 Pi 的世界里，"扩展"本身就是日常使用的一部分，不是"高级玩家才碰"的东西。

### 1.1 一个比喻

如果直接调 LLM API 像你**给一个人发了一条消息、等他回一条**，那 Agent 就像你**招了一个实习生**：你交代一个任务（"帮我把这个 bug 修了"），实习生不会只回一句话，而是自己翻文件、查资料、写代码、跑测试，中间可能来回好几轮，最后拿着结果来找你汇报。你可以在他干活的时候随时插话纠正方向（"等等，别动那个文件"），这就是 Agent 跟一次性 API 调用的根本区别——**它有主动性，因为它在一个循环里**。

### 1.2 常见误解

| 误解 | 事实 |
|------|------|
| ❌ "Agent 是一种特殊的 AI 模型" | ✅ Agent 是围绕**现有模型**写的一段循环代码。换模型不换循环，Agent 还是那个 Agent。 |
| ❌ "Agent 一定比直接调 API 慢/贵" | ✅ Agent 每一轮的 API 调用跟直接调一样快、一样贵。只是它可能调**多轮**，所以总开销取决于循环跑了多少圈。 |
| ❌ "function calling = Agent" | ✅ function calling 是 Agent Loop 里的一个**零件**——模型说"我要调这个函数"，你执行了把结果塞回去。没有循环的 function calling 不是 Agent，只是结构化输出。 |
| ❌ "Agent 能自己思考" | ✅ Agent 没有自主意识。它的"决定下一步"就是模型根据当前 messages 做的一次推理——跟你直接问模型没有本质区别，只是放在了循环里。 |

### 1.3 动手验证（5 分钟）

读到这里你可能觉得"懂了"——但亲眼看一次 Agent Loop 在跑，理解会深一层：

```bash
# 如果你还没安装 pi，先看第 3 章。装好后：
cd 任意一个 git 项目
pi -p "这个仓库有哪些文件？package.json 里有什么？"
```

你会看到模型先调 `ls` 列文件、再调 `read` 读 `package.json`——每调一次工具，结果都喂回去让模型决定下一步。这就是你刚才读的那个循环在跑。

> 如果你还不想安装，可以跳到第 3 章装好后再回来做这个练习。
