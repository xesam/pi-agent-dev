## 第 6b 章：实战 Level-2：安全编码守卫扩展

上一章你学会了创建子 Agent 会话。这一章换个方向——不做多 Agent，而是用事件拦截做一个**生产环境最实用的模式**：安全守卫。

**场景**：你在一个真实项目里用 Pi，希望它自由地写代码、跑命令，但有几条红线不能碰——不写 `.env`，不动 `.git/`，`rm -rf` 和 `git push --force` 要先问过你。

这正是第 5d 章 Mini-lab B 的完整版：从"拦一个命令"扩展到"一套安全策略"。

> **代码量**：约 80 行。读完本章你会有一个可以直接用在生产项目里的安全扩展。

### 6b.1 设计

```
安全守卫扩展做的事：

1. 拦截 write/edit → 检查路径 → 命中保护列表就 block
2. 拦截 bash     → 检查命令 → 危险命令弹确认
3. /safe 命令    → 切换安全模式开关
4. 状态持久化    → 用 pi.appendEntry 让开关状态跟会话分支走
```

其中第 4 点——"状态持久化"——是本章的新概念，参考了 Pi 官方的 `todo.ts` 示例。它解决的问题是：你开了一个会话、开了安全模式、然后 `/fork` 了一个分支——分支里应该是"开了"还是"关了"？答案：应该跟 fork 点的状态一致。`pi.appendEntry` 就是干这个的。

### 6b.2 代码

创建 `.pi/extensions/safe-coder/index.ts`：

```typescript
// 安全编码守卫扩展
//
// 功能：
// 1. 拦截对保护路径的 write/edit（.env、.git/、node_modules/）
// 2. 拦截危险 bash 命令（rm -rf、git push --force、sudo），弹确认
// 3. /safe 命令切换安全模式开关
// 4. 用 pi.appendEntry 持久化开关状态，支持会话分支
//
// 设计要点：
// - 保护路径和危险命令是硬约束（代码层 block），不靠 prompt
// - 安全模式开关本身也持久化到会话——fork 后状态正确

import type { ExtensionAPI, ExtensionContext } from "@earendil-works/pi-coding-agent";

// ── 安全策略配置 ──────────────────────────────────────────

const PROTECTED_PATHS = [".env", ".git/", "node_modules/"];

const DANGEROUS_COMMANDS = ["rm -rf", "git push --force", "git push -f", "sudo", "DROP TABLE"];

// ── 扩展入口 ──────────────────────────────────────────────

interface SafeState {
  enabled: boolean;
}

export default function (pi: ExtensionAPI) {
  let safeMode = true; // 默认开启

  // ── 4. 状态持久化：从会话历史重建开关状态 ──
  const reconstructState = (ctx: ExtensionContext) => {
    safeMode = true; // 默认值
    for (const entry of ctx.sessionManager.getBranch()) {
      if (entry.type === "custom" && entry.customType === "safe-coder-state") {
        const data = entry.data as SafeState | undefined;
        if (data) safeMode = data.enabled;
      }
    }
    updateStatus(ctx);
  };

  const updateStatus = (ctx: ExtensionContext) => {
    if (safeMode) {
      ctx.ui.setStatus("safe-coder", ctx.ui.theme.fg("warning", "🛡 safe"));
    } else {
      ctx.ui.setStatus("safe-coder", undefined);
    }
  };

  const persistState = (ctx: ExtensionContext) => {
    pi.appendEntry("safe-coder-state", { enabled: safeMode } as SafeState);
    updateStatus(ctx);
  };

  pi.on("session_start", async (_event, ctx) => {
    reconstructState(ctx);
    ctx.ui.notify(`safe-coder 已加载：安全模式 ${safeMode ? "开启" : "关闭"}`, "info");
  });

  pi.on("session_tree", async (_event, ctx) => {
    reconstructState(ctx);
  });

  // ── 3. /safe 命令：切换开关 ──
  pi.registerCommand("safe", {
    description: "切换安全模式（拦截危险操作）",
    handler: async (_args, ctx) => {
      safeMode = !safeMode;
      ctx.ui.notify(`安全模式已${safeMode ? "开启 🛡" : "关闭 ⚠️"}`, safeMode ? "info" : "warning");
      persistState(ctx);
    },
  });

  // ── 1. 拦截 write/edit：检查保护路径 ──
  pi.on("tool_call", async (event, ctx) => {
    if (!safeMode) return;

    // 拦截对保护路径的写入
    if (event.toolName === "write" || event.toolName === "edit") {
      const filePath = (event.input as { path?: string }).path ?? "";
      const isProtected = PROTECTED_PATHS.some((p) => filePath.includes(p));
      if (isProtected) {
        if (ctx.hasUI) {
          ctx.ui.notify(`🛡 已拦截对保护路径的写入：${filePath}`, "warning");
        }
        return { block: true, reason: `路径 "${filePath}" 受保护，写入被阻止` };
      }
    }

    // 拦截危险 bash 命令
    if (event.toolName === "bash") {
      const command = (event.input as { command?: string }).command ?? "";
      const isDangerous = DANGEROUS_COMMANDS.some((d) => command.includes(d));
      if (isDangerous && ctx.hasUI) {
        const ok = await ctx.ui.confirm(
          "🛡 危险操作确认",
          `即将执行：${command}\n\n确定要继续吗？`,
        );
        if (!ok) {
          return { block: true, reason: "被用户拦截" };
        }
      }
    }
  });
}
```

### 6b.3 新概念：状态持久化（pi.appendEntry）

这章最值得学的新东西是 `pi.appendEntry` + 会话重建模式。分三步看：

**第 1 步：写入状态**

```typescript
pi.appendEntry("safe-coder-state", { enabled: safeMode });
```

`appendEntry` 往会话历史里写一条"自定义条目"。这条记录会跟随会话一起持久化、一起 fork/branch。

**第 2 步：重建状态**

```typescript
const reconstructState = (ctx: ExtensionContext) => {
  safeMode = true; // 默认值
  for (const entry of ctx.sessionManager.getBranch()) {
    if (entry.type === "custom" && entry.customType === "safe-coder-state") {
      const data = entry.data as SafeState | undefined;
      if (data) safeMode = data.enabled;
    }
  }
};
```

`getBranch()` 返回当前分支的所有条目。我们从最后往前扫描，找到最后一条 `safe-coder-state` 记录，用它恢复状态。

**第 3 步：在正确的时机调用重建**

```typescript
pi.on("session_start", async (_event, ctx) => reconstructState(ctx));
pi.on("session_tree", async (_event, ctx) => reconstructState(ctx));
```

- `session_start` — 会话启动时（包括 resume）
- `session_tree` — 用 `/tree` 导航到历史某点时

这样保证了：你开了安全模式 → 写了几行代码 → `/fork` 了一个分支 → 分支里安全模式是开的。再 `/tree` 回到开之前的位置 → 安全模式恢复成之前的状态。

> **为什么不用全局变量记就行？** 因为会话可以 fork、可以 tree-navigate。如果只用内存变量，fork 后两个分支共享同一个变量——改一个影响另一个。`appendEntry` 让状态跟会话分支走，每个分支有自己正确的状态。

```bash
cd 你的项目目录
pi

```

```
帮我在 .env 文件里写一个数据库连接字符串
```

→ 你会看到 `🛡 已拦截对保护路径的写入：.env`

测试危险命令确认：

```
帮我删掉 /tmp/test 目录
```

→ 如果 Pi 用 `rm -rf /tmp/test`，会弹出确认框

测试开关切换：

```
/safe
```

→ 状态栏显示安全模式已关闭，之后危险操作不再拦截。再 `/safe` 重新开启。

### 6b.5 排错提示

- **保护路径没有生效**：检查 `safeMode` 是否为 `true`（状态栏有没有 🛡），检查文件路径是否真的包含了 `.env` / `.git/` 等字符串
- **`/safe` 切换后状态没保存**：确认 `pi.appendEntry` 被调用了，检查 `persistState` 函数
- **确认框没弹出**：`ctx.ui.confirm` 只在 TUI 交互模式下有效。如果你用 `pi -p`（非交互模式）则不会有 UI
- **fork 后状态不对**：确认 `session_tree` 事件里调用了 `reconstructState`

### 6b.6 这个模式在官方示例里叫什么

Pi 官方仓库的 `examples/extensions/` 里有几个类似设计：

| 官方示例 | 做了什么 | 与本章的关系 |
|---------|---------|-------------|
| `protected-paths.ts` | 拦截对保护路径的写入 | 本章的第 1 部分的简化版 |
| `confirm-destructive.ts` | 拦截危险会话操作（clear/switch） | 思路一样，拦截对象不同 |
| `todo.ts` | `appendEntry` 状态持久化 + 重建 | 本章的第 4 部分的参考 |

本章把这些模式组合在一起，形成了一个可直接使用的"安全守卫"扩展。
